# Version facts live behind a live URL anchor, never baked into a SKILL.md

ArcGIS version relationships change over time — for example, Experience Builder production build commands and output paths differ across releases — so any `SKILL.md` that hardcodes a version-specific fact becomes confidently wrong later. Each version-needing skill therefore encodes the _procedure_ for discovering the version and points a context pointer at the live Esri version-matrix URL, which stays the single source of truth for the Enterprise↔SDK↔Calcite↔Arcade mapping. `exb-widget` additionally keeps a local [VERSIONS.md](../../skills/arcgis/exb-widget/VERSIONS.md) lookup procedure for runtime pairing, exact-release Node/package-manager requirements, and installed build configuration. Runtime compatibility still requires validation on each promised target.

> Corrected 2026-09-24: this ADR previously placed the `build:prod` / `dist-prod` to `build:for-download` / `dist-download` transition at 1.17. Esri's Enterprise hosting docs say **1.17 and earlier** use the old command/output. The version reference records that discrepancy; check the actual installation before relying on a cutoff.

> Amended by [ADR-0006](0006-admit-server-side-skills-per-stack-anchor.md): the "single" live anchor is now understood as _per-stack_. The JS SDK version-matrix remains the anchor shared by the JS-family skills; `arcgis-custom-data-feeds` points instead at the ArcGIS Enterprise SDK CDF guide, a separate release train. The principle — point at the live owner, never restate — is unchanged.
